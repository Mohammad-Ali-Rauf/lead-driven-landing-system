# LeadGen Pro

Self-hosted landing page + lead capture backend. No CMS, no third-party forms, no subscriptions.

## Quick Start

```bash
git clone <repo-url> leadgen && cd leadgen
./setup.sh              # creates .env with a secure AUTH_SECRET
# edit .env — set ADMIN_PIN to something you'll remember
docker compose up -d
# → http://localhost:3000
```

## Features

- Landing page with lead capture form
- PIN-protected admin dashboard (stats, search, CSV/JSON export)
- Local SQLite storage — no external services
- Mobile-first, responsive design
- Client + server-side validation
- CSP, CSRF, rate limiting, HttpOnly cookies

## Configuration

| Variable | Required | Description |
|---|---|---|
| `ADMIN_PIN` | Yes | Admin login PIN |
| `AUTH_SECRET` | Yes | Cookie signing key (generated by `setup.sh`) |

<details>
<summary><b>Without Docker</b></summary>

```bash
pnpm install
cp .env.example .env
# generate AUTH_SECRET: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
pnpm dev        # development
pnpm build && pnpm start  # production
```
</details>

<details>
<summary><b>Usage</b></summary>

- **Landing page** — `http://localhost:3000`. Visitors fill out the contact form.
- **Admin dashboard** — `http://localhost:3000/admin`. Enter your PIN to view leads, search, and export.
</details>

<details>
<summary><b>Deployment</b></summary>

**Docker (recommended):** `docker compose up -d` on any VPS. Use nginx/Caddy for TLS.

**Vercel:** Add `ADMIN_PIN` and `AUTH_SECRET` as environment variables.
> SQLite is ephemeral on Vercel — data resets on each deploy.

**Other platforms (Railway, Fly.io):** Set env vars, start command `pnpm start`.
</details>

<details>
<summary><b>Security</b></summary>

- SHA-256 hashed PIN + secret salt, compared with `crypto.timingSafeEqual`
- HttpOnly, SameSite=Lax auth cookie
- CSRF token header on state-changing endpoints
- Rate limited login (5/min per IP)
- Security headers via middleware (CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy)
- Parameterized SQL queries (sql.js prepared statements)
- Client + server input validation with max length limits
- Non-root `nextjs` user in Docker
</details>
